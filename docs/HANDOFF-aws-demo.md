## 3. Architectural notes you must know before touching anything

### 3.1 Per-deployment terraform modules (not per-service)

Full rationale: `pi-terraform/RAMP-DEMO.md`. TL;DR:

- Legacy `aws-ec2`, `aws-s3`, `aws-lambda`, `aws-cloudfront`, `aws-acm` are **per-service** and house every project's resources. Putting ramp-demo there forced `<DEPLOYER_PROFILE>` to need broad cross-project read + write perms.
- We extracted ramp-demo into **per-deployment** modules: `aws-ramp-demo-{acm,ecs,lambda,s3,cloudfront}` each with its own backend state key.
- **Don't put new ramp-demo resources in the legacy modules** — put them in the `aws-ramp-demo-*` ones. Otherwise <DEPLOYER_PROFILE>'s policy has to be widened.

### 3.2 Lambda@Edge is the sole gate; no CloudFront trusted_key_groups

- The default cache behavior's `trusted_key_groups` is **explicitly set to `[]`** (not omitted — terraform provider 6.0 treats `omitted` as "don't change," so you must `trusted_key_groups = []` to actually remove them).
- The Lambda (v3, `pi-terraform/AWS/us-east-1/aws-ramp-demo-lambda/aws-lambda-ramp-demo-edge/index.mjs`) decides:
  - Query has `Signature=` → pass (bot self-identified as negotiated)
  - UA matches bot patterns → 403 + JSON body with `{error, exchange, ramp_json, mcp_endpoints}` + `X-Content-Rules` + `X-Ramp-Mcp` headers
  - Otherwise → pass (human)
- Every invocation logs structured JSON to CloudWatch (edge region). The logs are under `/aws/lambda/us-east-1.ramp-demo-edge-bot-redirect` in **each region where the edge POP ran the function** (not just us-east-1).
- **Security trade-off documented in the tf:** Lambda does NOT cryptographically verify the signature — it treats the presence of `Signature=` as proof of negotiation. Production would add RSA verification in the Lambda or route signed paths through trusted_key_groups.
- `/.well-known/*` has a dedicated ordered_cache_behavior with no Lambda and no signing, so `ramp.json` is always fetchable (otherwise bots would 403-loop when trying to follow X-Content-Rules).

### 3.3 IAM policy `pi_poc_ramp_demo` — 6144-byte cap

Size currently ~6042 bytes. If you need to extend it, **you must shrink something else or split** into a second attached policy.

Shrinking tricks that worked:
- Action wildcards (`ecr:*`, `secretsmanager:*`, `s3:*`) are safe when `Resource` is ARN-scoped to ramp-demo-prefixed resources.
- Account-level metadata reads (`ec2:Describe*`, `route53:List*/Get*`, `iam:ListPolicies`) can be on `Resource: "*"` — they're read-only.
- State bucket ARNs: use wildcards like `arn:aws:s3:::pi-tfstate/aws/*/ramp-demo-*/terraform.tfstate` instead of enumerating.

**Policy lives at** `pi-terraform/AWS/global/aws-iam/aws-iam_policy_json/pi_poc_ramp_demo.json`. Changes there require admin apply:
```bash
cd pi-terraform/AWS/global/aws-iam
AWS_PROFILE=<ADMIN_PROFILE> terraform apply
```

### 3.4 `ramp.json` has a `ramp-0.4-draft` extension

Our manifest advertises an `mcp_endpoints[]` array pointing at our MCP server:
```json
{
  "ver": "0.3",
  "provider": "demo.ramp-protocol.org",
  "exchanges": [...],
  "mcp_endpoints": [{
    "url": "https://mcp.demo.ramp-protocol.org/mcp",
    "transport": "http-streamable",
    "extension": "ramp-0.4-draft"
  }]
}
```

User's stance: announcing MCPs is fine; **auto-connecting** would be a security hole (anyone could prompt-inject an arbitrary MCP and get tool invocation). Don't remove the `extension` tag — it's the marker that says "experimental, not in the standard yet."

### 3.5 The Lambda@Edge 403 body also announces the MCP

Same structure as ramp.json, plus an `X-Ramp-Mcp` response header. That's what Claude picked up in the last test.

## 5. The remaining work (immediate next step)

### 5.1 The failure mode

**MCP `ramp_fetch(uri=...)` flow:**
1. MCP → `Broker POST /broker/v1/resolve` with URI ✅
2. Broker extracts domain, probes `ramp.json`, reads `exchanges[].endpoint` ✅
3. Broker calls `h.deps.Marketplaces.GetByDomain("exchange.demo.ramp-protocol.org")` — **returns `ErrNotFound`** ❌
4. `marketplacesFor` returns empty slice + `licensed=false`
5. Broker response: `{licensed: false, bare_url: "<original uri>"}`
6. MCP fetches `bare_url` via httpx (UA `python-httpx/*`) → our Lambda@Edge blocks (`python-httpx` pattern) → 403
7. MCP returns error to Claude

The Broker has a **Postgres-backed marketplace registry** it consults before trusting any exchange advertised in ramp.json. That table is empty.

### 5.2 What to seed and how

Three-part fix:

**(a) Broker — register our Exchange in the `broker.marketplaces` table.**
- Look at `src/broker/internal/db/migrations/` for the table schema.
- Add `POST /admin/seed` to Broker's `cmd/server/main.go` — same pattern as the Exchange's `/admin/seed` already has (`src/exchange/cmd/server/main.go`, look for `seedHandler`).
- Seed: domain=`exchange.demo.ramp-protocol.org`, endpoint=`https://exchange.demo.ramp-protocol.org`, trust_level=`TRUSTED`, healthy=true, and whatever other fields the schema has.
- Push image, roll broker service, curl the seed endpoint.

**(b) Exchange — register the Broker as an agent.**
- The Exchange's `ExecuteTransaction` RPC checks that the requesting agent is registered in `ramp.agents` (public_key + agent_id).
- Generate an Ed25519 keypair for the Broker (e.g., `openssl genpkey -algorithm ed25519`).
- Extend the Exchange's `/admin/seed` to accept `agents[]`. The schema is:
  ```
  agent_id (TEXT PK), public_key (BYTEA), manifest_url (TEXT?), requester_type (enum: AGENT|HUMAN_TOOL|SERVICE|DELEGATED|RESEARCH)
  ```
  See `src/exchange/internal/db/migrations/000001_init.up.sql`.
- Store the agent_id in config, store the private key in `ramp-demo/broker-ed25519-private` secret.
- Broker reads that secret at startup and uses the private key to sign RPC requests (RFC 9421 HTTP Message Signatures — check `src/broker/internal/transport/` for where signing happens).

**(c) Exchange — billing balance for the Broker's agent.**
- `EXCHANGE_BILLING_SEED` env var is JSON: `{"<agent_id>": {"value": "100.00", "currency": "USD"}}`.
- Goes on the `ramp-demo-exchange` ECS task definition as an env var (or inject via Secrets Manager reference). Look at `pi-terraform/AWS/us-east-1/aws-ramp-demo-ecs/ecs.tf` — the Exchange task definition already uses `secrets[]` from Secrets Manager. You can add an env with a plain value, or create a new secret.
- Without this, `ExecuteTransaction` denies with `INSUFFICIENT_BALANCE` at minted-URL time.

**(d) Fix the EXA key (cosmetic but user-visible).**
- `AWS_PROFILE=<DEPLOYER_PROFILE> aws secretsmanager put-secret-value --region us-east-1 --secret-id ramp-demo/exa-api-key --secret-string ""`
- Roll the broker. With empty key, Broker uses `StaticClient` (returns zero results for `query`-path calls). Claude will see `no domains for query` instead of a 502; cleaner failure mode.
- OR: plug in a real EXA API key if you want the query-path to do actual discovery.

## 6. Gotchas that bit us (don't repeat)

| Symptom | Cause | Fix |
|---------|-------|-----|
| `"service: unbound variable"` in `scripts/ecr-push.sh` | bash 3.2 + `set -u` + `local a=$1 b=$2` on one line | Split into separate `local` declarations |
| AWS rejected SG: `Character sets beyond ASCII` | em-dash `—` in SG description | Use plain `-` |
| RDS DSN parse error `invalid port ":XYZ..."` | random_password has `:?` chars that break URL parsing | URL-encode in `wire-secrets.sh` (done) |
| `terraform apply` claimed 1 changed but `trusted_key_groups` still live | provider 6.0 treats omitted field as unchanged | Explicit `trusted_key_groups = []` |
| CloudFront still serving old behavior after apply | Distro `Status: InProgress` ~2-5 min after apply | Wait `until ... Deployed`; invalidate cache if content changed (`cloudfront create-invalidation`) |
| Lambda@Edge logs missing | Logs are in the **edge region** (where POP ran), not us-east-1 | Scan all regions' `/aws/lambda/us-east-1.ramp-demo-edge-bot-redirect` |
| ACM cert request 403'd | `route53:ListTagsForResource` not in <DEPLOYER_PROFILE> policy | Added `route53:List*`, `route53:Get*` on `*` |
| RDS refresh 403'd on `db:*` ARN | `rds:Describe*` only matches scoped ARN; List calls need `*` | Moved `rds:Describe*` to UnavoidableAccountReads |
| ElastiCache `CreateCacheCluster` 403 on `parametergroup:default.redis7` | My policy scoped to cluster/subnetgroup only | Added `parametergroup:default.*` to ElastiCache resource list |
| `<ADMIN_PROFILE>` profile used for log reads | Original policy scoped logs to `/aws/lambda/ramp-demo-*` (no prefix), Lambda@Edge adds `us-east-1.` prefix | Broadened to `/aws/lambda/*.ramp-demo-*` + `arn:aws:logs:*:...` (cross-region) |
| Resource ARN mismatch — `postgres-ramp-demo` vs `ramp-demo-*` | pre-existing names didn't match policy prefix | Renamed tf resources to `ramp-demo-postgres` |
| `ec2:CreateSecurityGroup` with `aws:RequestTag/Project` condition denied | `default_tags` not reliably in `TagSpecifications` for this API in aws provider 6.x | Drop the `aws:RequestTag` condition on CreateSG (accept broader create; modifications still ResourceTag-gated) |
| Claude hallucinated a "fetch" that never hit our edge | Claude's `web_fetch` got 403, then LLM generated from training data disguised as paraphrase | Canary test (inject fabricated token in article content; ask LLM to quote it back). Missing canary = didn't fetch. |

## 8. Debugging recipes

### 8.1 Find the Lambda@Edge decision for a specific request

```bash
CUTOFF=$(( $(date +%s)000 - 1800000 ))  # last 30 min
for region in us-east-1 us-east-2 us-west-1 us-west-2 eu-west-1 eu-central-1 eu-north-1 ap-south-1 ap-northeast-1; do
  STREAMS=$(AWS_PROFILE=<DEPLOYER_PROFILE> aws logs describe-log-streams --region $region \
    --log-group-name "/aws/lambda/us-east-1.ramp-demo-edge-bot-redirect" \
    --query "logStreams[?lastEventTimestamp>=\`$CUTOFF\`].logStreamName" --output text 2>/dev/null)
  for s in $STREAMS; do
    AWS_PROFILE=<DEPLOYER_PROFILE> aws logs get-log-events --region $region \
      --log-group-name "/aws/lambda/us-east-1.ramp-demo-edge-bot-redirect" \
      --log-stream-name "$s" --start-time $CUTOFF 2>/dev/null \
      | python3 -c "
import sys, json, datetime
d = json.load(sys.stdin)
for e in d['events']:
    m = e['message'].strip()
    if 'ramp-demo-edge' in m:
        p = json.loads(m[m.index('{'):])
        t = datetime.datetime.fromtimestamp(e['timestamp']/1000, tz=datetime.timezone.utc).isoformat(timespec='seconds')
        print(f\"{t} | $region | {p['decision']:13s} | bot={(p.get('bot_pattern') or '-'):15s} | uri={p['uri']} | UA={p['ua']}\")
"
  done
done 2>&1 | sort -u
```
